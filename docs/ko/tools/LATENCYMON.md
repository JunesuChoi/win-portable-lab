# LatencyMon 상세 사용법

드라이버가 커널에서 너무 오래 실행돼 실시간 처리를 방해하는지 측정합니다. 온도와 클럭은 정상인데 소리가 끊기거나, 프레임이 일정하지 않거나, 마우스가 순간적으로 멈추는 증상의 원인을 찾을 때 씁니다. HWiNFO 센서 기록으로는 보이지 않는 영역입니다.

실행 ID는 `latencymon`이고 읽기 전용이지만 관리자 권한이 필요합니다.

## 측정 원리

- ISR은 인터럽트 서비스 루틴입니다. 하드웨어 인터럽트를 즉시 처리하는 코드입니다.
- DPC는 지연 프로시저 호출입니다. ISR이 미룬 작업을 이어서 처리합니다.
- 이 둘이 오래 점유하면 오디오 버퍼가 비거나 프레임 전달이 늦어집니다. LatencyMon은 각 드라이버가 얼마나 오래 점유했는지 측정합니다.

## 실행 방법

1. 문제가 재현되는 환경을 그대로 만듭니다. 평소 쓰는 프로그램을 켠 상태여야 원인이 드러납니다.
2. LatencyMon을 관리자 권한으로 실행합니다.
3. 상단 재생 버튼으로 측정을 시작합니다.
4. 최소 10분 이상 측정합니다. 증상이 간헐적이라면 증상이 한 번 이상 나타날 만큼 오래 돌립니다.

## 탭 해석

| 탭 | 무엇을 보는가 | 핵심 |
|---|---|---|
| Main | 종합 판정 문구 | 실시간 오디오 적합 여부를 문장으로 알려줍니다 |
| Stats | 최대 DPC·ISR 지연과 인터럽트 수 | 최대값과 평균을 함께 봅니다 |
| Drivers | 드라이버별 점유 시간 | `Highest execution` 기준으로 정렬해 상위 항목을 봅니다 |
| Processes | 프로세스별 하드 페이지 폴트 | 특정 프로그램이 원인일 때 드러납니다 |
| Stacks | 커널 스택 샘플 | 심층 분석용 |

## 판정 기준

| 최대 DPC·ISR 지연 | 해석 |
|---|---|
| 500마이크로초 미만 | 양호. 실시간 오디오에 문제 없음 |
| 500에서 1000마이크로초 | 주의. 낮은 버퍼 설정에서 끊김 가능 |
| 1000에서 4000마이크로초 | 문제 있음. 원인 드라이버를 찾아야 함 |
| 4000마이크로초 초과 | 심각. 체감 증상이 발생하는 수준 |

Drivers 탭에서 상위에 오른 드라이버 파일명이 원인 후보입니다. 자주 등장하는 것들의 성격은 다음과 같습니다.

| 파일 | 담당 | 대응 |
|---|---|---|
| `ndis.sys` | 네트워크 | 랜·와이파이 드라이버 갱신, 절전 옵션 해제 |
| `nvlddmkm.sys` | NVIDIA 그래픽 | 드라이버 갱신 또는 DDU 후 클린 설치 |
| `amdkmdag.sys` | AMD 그래픽 | 위와 동일 |
| `storport.sys` | 저장장치 | 칩셋·NVMe 드라이버 갱신, SMART 확인 |
| `ACPI.sys` | 전원 관리 | BIOS 갱신, C-State 관련 설정 검토 |
| `dxgkrnl.sys` | 그래픽 커널 | 그래픽 드라이버와 함께 검토 |
| `wdf01000.sys` | 드라이버 프레임워크 | 하위 장치 드라이버 추적 필요 |

## 개선 순서

1. 상위 드라이버에 해당하는 장치 드라이버를 최신 정식 버전으로 갱신합니다.
2. 그래픽이 원인이면 DDU로 완전 제거한 뒤 클린 설치합니다.
3. 네트워크가 원인이면 어댑터 속성에서 절전 기능을 끕니다.
4. 전원 관리가 원인이면 BIOS를 갱신하고 과도한 절전 설정을 검토합니다.
5. 변경 후 같은 조건으로 다시 측정해 수치가 내려갔는지 확인합니다.

한 번에 하나만 바꾸고 재측정합니다. 여러 개를 동시에 바꾸면 무엇이 효과가 있었는지 알 수 없습니다.

## 주의

측정 자체는 읽기 전용이지만 커널 수준 관찰이므로 관리자 권한이 필요합니다. Home Edition은 개인 사용에 한해 무료입니다. 업무용으로는 라이선스가 필요합니다.

```powershell
.\scripts\Open-PortableTool.ps1 -Root . -Id latencymon -Language ko
```
