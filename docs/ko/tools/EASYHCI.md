# EasyHCI 상세 사용법

무료판 HCI MemTest를 자동으로 굴려주는 한글 런처입니다. HCI MemTest 자체는 명령줄도, 로그도, 멀티스레드도 없어서 인스턴스를 사람이 여러 개 띄우고 크기를 일일이 계산해야 합니다. EasyHCI는 그 계산과 반복을 대신합니다.

실행 ID는 `easyhci`이고 위험도는 고부하입니다. 실제 부하는 EasyHCI가 띄우는 memtest.exe가 만듭니다.

## 준비

memtest.exe는 이 팩에 포함되어 있지 않습니다. HCI MemTest는 HCI Design의 독점 프리웨어라 재배포와 다른 프로그램 내장에 허가가 필요하기 때문입니다.

1. [hcidesign.com/memtest](https://hcidesign.com/memtest/)에서 무료판을 받습니다.
2. 받은 `memtest.exe`를 EasyHCI 옆에 두거나, 이 팩의 도구 폴더에 넣어두면 됩니다.

런처는 아래 순서로 찾고, 못 찾으면 찾아본 경로를 전부 보여주는 안내 창을 띄웁니다.

| 순서 | 위치 |
|---|---|
| 1 | `Resources\memtest_path.txt`에 적힌 경로 |
| 2 | `Resources\memtest.exe` |
| 3 | EasyHCI.exe와 같은 폴더 |
| 4 | 상위 폴더로 최대 6단계 올라가며 `hci-memtest\memtest.exe` |
| 5 | 같은 단계의 `tools` 폴더 안에서 이름에 `hci`나 `memtest`가 들어간 폴더 |

5번 덕분에 이 팩의 HCI MemTest를 내려받아 두었다면 따로 설정할 필요가 없습니다.

## 실행 방법

1. `설정` 탭에서 목표 커버리지를 정합니다. 비워두거나 기본값이어도 동작합니다.
2. `테스트` 탭에서 테스트를 시작합니다.
3. 진행 상황은 `테스트` 탭에서 확인합니다. 오래 걸리므로 잘 때나 외출할 때 돌리는 편이 좋습니다.

시작할 때 "불필요한 모든 프로세스를 종료하시겠습니까?"를 묻습니다. 무료판은 미할당 메모리만 검사하므로, 다른 프로그램을 닫아야 검사 범위가 넓어집니다. 예외로 둘 프로세스는 `Resources\Process_Exceptions.ini`에 적습니다.

## 자동으로 처리하는 것

| 항목 | 동작 |
|---|---|
| 인스턴스당 할당량 | 여유 메모리와 CPU 쓰레드 수로 최대 할당 가능량을 탐색 |
| 인스턴스 수 | 논리 코어 수에 맞춰 실행 |
| 커버리지 집계 | 여러 창의 진행률을 모아 표시 |
| 화면 캡처 | 지정한 주기로 스크린샷 저장 |
| 알림음 | 성공·오류를 소리로 구분 |
| 로그 | 종료 시 `EasyHCI_Log.txt`에 기록 |
| 마지막 행동 | 완료 후 자동 종료, 절전, 시스템 종료 중 선택 |

## 판정 기준

- `Coverage`: 누적 진행률입니다. 100%가 1회 완주이고, 오래 돌릴수록 200%, 400%로 쌓입니다.
- `Errors`: 0이어야 합니다. 1이라도 나오면 그 오버클럭은 실패입니다.
- 테스트 중 메모리 사용량이 95% 이상 유지되어야 결과를 믿을 수 있습니다.

## 주의

- 관리자 권한으로 실행됩니다. HCI MemTest가 큰 메모리를 잡으려면 필요합니다.
- 장시간 통과해도 실사용에서 문제가 생길 수 있습니다. 대개는 램 온도 문제이고, 게임 중에는 GPU 열기까지 더해집니다. 높은 전압으로 오버클럭했다면 램 스팟쿨링을 권합니다.
- HCI MemTest만으로 충분하지 않습니다. [TESTMEM5](TESTMEM5.md)나 Prime95와 함께 쓰는 편이 좋습니다.
- 무료판 자체의 제약은 [HCI_MEMTEST](HCI_MEMTEST.md)에 정리해 두었습니다.
