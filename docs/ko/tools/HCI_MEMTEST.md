# HCI MemTest 상세 사용법

메모리 오류를 커버리지 비율로 누적 검증하는 도구입니다. TM5가 짧은 시간에 오류를 잡는 데 강하다면, HCI MemTest는 오래 돌려 누적 커버리지로 신뢰도를 쌓는 쪽입니다.

실행 ID는 `hci-memtest`이고 위험도는 고부하입니다.

## 무료판의 한계

이 프로젝트는 무료판만 포함합니다. 유료판은 재배포할 수 없습니다. 무료판에는 아래 제약이 있습니다.

| 항목 | 무료판 | 유료 Pro |
|---|---|---|
| 검사 대상 | Windows가 할당하지 않은 메모리만 | 가용 메모리 자동 분배 |
| 멀티스레드 | 없음. 인스턴스를 여러 개 수동 실행 | 네이티브 멀티스레드 |
| 명령줄 자동화 | 없음 | 있음 |
| 로그 파일 | 없음 | 오류 로그 저장 |

자동화와 로그가 없기 때문에 이 도구의 결과는 다른 도구처럼 세션 기록에 자동으로 남지 않습니다. 결과는 화면을 직접 확인하고 필요하면 스크린샷으로 보관합니다.

## 실행 방법

1. 다른 프로그램을 최대한 닫습니다. 무료판은 미할당 메모리만 검사하므로, 다른 프로그램이 메모리를 점유하면 검사 범위가 줄어듭니다.
2. 총 메모리에서 운영체제 몫을 제외한 양을 인스턴스 수로 나눕니다. 예를 들어 64GB 시스템에서 논리 코어가 8개라면, 약 56GB를 8로 나눠 인스턴스당 7000MB 정도를 배정합니다.
3. 인스턴스를 논리 코어 수만큼 실행합니다. 각 창에 위에서 계산한 크기를 입력합니다.
4. 모든 창에서 `Start Testing`을 누릅니다.

입력란을 비우거나 `All unused RAM`을 쓰면 첫 인스턴스가 남은 메모리를 모두 차지해 나머지가 제대로 배정되지 않습니다. 크기를 명시하는 편이 안전합니다.

## 화면 해석

- `Coverage`: 검사 진행 비율입니다. 100%가 1회 완주입니다. 계속 돌리면 200%, 400%처럼 누적됩니다.
- `Errors`: 반드시 0이어야 합니다.

## 판정 기준

| 목적 | 권장 커버리지 | 통과 조건 |
|---|---|---|
| 빠른 확인 | 400% | 오류 0 |
| 일반 사용 | 1000% | 오류 0 |
| 24시간 가동 시스템 | 5000% 이상 | 전 구간 오류 0 |
| 무결성이 중요한 작업용 | 10000% | 전 구간 오류 0 |

커버리지 목표가 높을수록 시간이 오래 걸립니다. 5000%는 보통 하룻밤 이상 소요됩니다. 창 하나라도 오류가 1 이상이면 전체가 실패입니다.

## 즉시 중단 조건

- 어느 창이든 오류가 1 이상 표시될 때
- 메모리 또는 CPU 온도가 한계에 접근할 때
- 시스템이 멈추거나 재부팅될 때
- 이벤트 로그에 WHEA 오류가 기록될 때

## 다른 도구와의 관계

TM5로 먼저 걸러내고, 통과한 설정을 HCI MemTest로 오래 돌려 확인하는 순서가 효율적입니다. TM5는 짧게 오류를 잡고, HCI MemTest는 시간을 들여 놓친 오류를 찾습니다. 운영체제 영향을 완전히 배제하려면 MemTest86+로 부팅 검사를 합니다.

```powershell
.\scripts\Open-PortableTool.ps1 -Root . -Id hci-memtest -AcknowledgeRisk -Language ko
```
